04 · Problem-solving

Problem-solving

Five troubleshooting cases, one security case and my responsible use of AI.

Case 1 · Web

Images not loading on mobile

Problem: Portfolio images appeared broken only on mobile browsers.

Causes considered: wrong relative paths, case-sensitive filenames, missing assets folder on host.

Diagnostic: Checked network tab, confirmed 404s, compared local vs deployed file structure.

Solution: Normalized all asset paths and uploaded the missing images folder.

Lesson: Always verify case sensitivity and relative paths after deploy.

Case 2 · Data

Excel formulas returning #DIV/0!

Problem: Average order-value formulas failed on empty promo groups.

Causes: Division by zero when a category had zero rows.

Diagnostic: Used COUNTIF to confirm empty groups.

Solution: Wrapped averages with IF(COUNTIF(...)=0,"—",AVERAGEIFS(...)).

Lesson: Guard every division and average against empty sets.

Case 3 · JS

Theme toggle not persisting

Problem: Dark mode reset on page reload.

Causes: localStorage write failing in private mode or missing read on load.

Diagnostic: Console checked for quota/security errors.

Solution: Wrapped storage in try/catch and applied stored theme immediately on DOM load.

Lesson: Treat browser storage as optional and fail gracefully.

Case 4 · SQL

Slow query on student records

Problem: SELECT with multiple JOINs timed out on a class project database.

Causes: Missing indexes on foreign keys and SELECT * pulling unused columns.

Diagnostic: EXPLAIN showed full table scans.

Solution: Added indexes on join columns and selected only needed fields.

Lesson: Index early and avoid SELECT * in production queries.

Case 5 · Deployment

Contact form opened blank email

Problem: mailto: link produced empty subject/body on some phones.

Causes: Unencoded special characters and missing encodeURIComponent.

Diagnostic: Tested on Android and iOS mail clients.

Solution: Properly encoded subject and body with encodeURIComponent.

Lesson: Always encode dynamic parts of mailto URLs.

Cybersecurity case study

Security · SQL Injection

Preventing SQL injection in a login form

What it is: Attackers inject malicious SQL through form inputs to bypass authentication or read data.

How it happens: User input is concatenated directly into a query string, e.g. "SELECT * FROM users WHERE name='" + input + "'".

Risks: Unauthorized access, data theft, data destruction, privilege escalation.

Prevention: Use parameterized queries / prepared statements, validate and sanitize input, apply least-privilege database accounts, and never trust client-side checks alone.

Practices I apply: Prefer ORMs or prepared statements, keep credentials out of source control, and review any raw SQL carefully.

Reflection

Looking back on the BSIT program so far.

Reflection

What I’ve learned and where I’m going

Before BSIT I knew computers mostly as a user—browsing, school work and a little curiosity about how websites were made. I had no clear picture of software development, databases or the discipline needed to turn an idea into a working system.

The most important things I have learned are how to break a problem into smaller steps, how to read and write code that other people can understand, and how data can reveal patterns that help real decisions. Courses in programming, databases and systems analysis forced me to move from “it works on my machine” to “it works for the user and can be maintained.”

The project that taught me the most is the Food Delivery Analysis workbook. Cleaning the data, writing formulas, calculating correlations and then turning numbers into concrete recommendations showed me that technical skill only matters when it produces clear, usable insight. Presenting the findings also improved my ability to explain technical work to non-technical listeners.

The hardest technical difficulty so far has been debugging—especially when a page looks fine but behaves differently on another device or when a query returns unexpected rows. Learning to use browser DevTools, EXPLAIN plans and careful logging has made me slower to assume and faster to verify.

My IT skills have grown from basic HTML pages to responsive layouts, simple JavaScript interactivity, Python scripts, SQL queries and structured Excel analysis. Soft skills—communication, responsibility and working with others—have improved through group projects and part-time work.

I still need to improve modern frontend frameworks, API design, testing habits and deployment workflows. I also want stronger habits around version control and documentation.

I want to become a reliable junior web developer who can take a feature from requirements to a working, accessible interface, communicate clearly with teammates, and keep learning. Over time I hope to grow into a full-stack role where I can mentor others and help deliver software that people actually use.

I am ready to begin a career in IT because I have practiced the fundamentals, completed projects that demonstrate those skills, and developed the curiosity and persistence needed to keep improving. I know I still have a lot to learn, and I am prepared to learn it on the job.
